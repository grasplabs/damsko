## Voice

Say it as a helpful colleague would, in the fewest plain words that are still clear: never blaming, never cute.

<Stage path="guidelines/writing-voice" label="Voice" />

## Buttons

A verb and the thing it acts on, so the button promises exactly what happens when it is pressed.

<Stage path="guidelines/writing-buttons" label="Buttons" />

## While it works and after

The button shows a spinner and says Saving, then shows Saved or Not saved, so nothing happens in silence. Press each one.

A result on a button is one or two words: Saved, Sent, Not saved, Not loaded. The button keeps the width of its longest words, so a long result makes a short action wide; why it failed goes in the line or the toast beside it, never on the button.

<Stage path="guidelines/writing-progress" label="While it works and after" />

## Questions before a step

One question that names the thing and what is lost, answered with the same verb: Delete Quarterly review? Delete, or Keep it.

<Stage path="guidelines/writing-questions" label="Questions before a step" />

Say what is happening: Thinking, then Thought for 4 seconds. Never Loading where a truer word exists, nor an ellipsis for a word.

## Confirmations and undo

## Status words

A state is said in a word, never by [colour alone](/guidelines/accessibility#colour-and-contrast), and the same state takes the same word everywhere.

## Numbers, dates and plurals

Real figures, as a person reads them: No sources, 1 source, 12 sources, Tuesday 14:02. The words are functions, so each language pluralises.


## Words as props, and translation

Every word shown or said is a prop with an English default, never glued from pieces. German and Dutch run a third longer.

```tsx
<I18nProvider locale="nl-NL" catalog={nl}>
  <MessageError onRetry={retry}>
    Kon niet antwoorden. De agenda reageerde niet.
  </MessageError>
</I18nProvider>
```

## One instance's own words

The product gives every part its words once per root, in its language, through `I18nProvider`, with a catalogue (`I18nCatalog` in `src/lib/i18n.tsx`) keyed by part: `message`, `audioPlayer`, `appShell01`. A part in one place can say something of its own: the error under one answer says why it failed, not only "Could not answer". Give that instance its words through its own children or prop:

```tsx
<MessageError onRetry={retry}>Could not answer. The calendar did not respond.</MessageError>
<MessageActions aria-label="Answer actions">…</MessageActions>
<Button onClick={saveName} errorText="Could not save. Your name is kept.">Save</Button>
```

Each such prop wins over the catalogue for that instance only. Words it leaves out come from the catalogue, else English. Only words that differ from the catalogue need giving. A word the catalogue gives as a function (`count: (count) => …`) is given as a function, so each language pluralises.

The catalogue is a `Partial<I18nCatalog>`, partial by part: a part it leaves out keeps its English, and a part it gives, it gives whole. A word added to a part in Damsko then fails the product's type check at its next update, until it is translated. Providers do not merge: an inner one replaces the outer one's words for what it wraps, so give one per root.

## Words from a translation library

A product whose words come from a translation library (Lingui, i18next, FormatJS) has no constant to give: the words exist once a language is active, and change with it. Build the catalogue where the library's words are read, while rendering, in one component around the routes. The provider keeps the words it has until `locale` or one of the strings changes, so nothing that reads them is drawn again because the object is a new one; a word that is a function is read again at the same moment. `locale` is required for that reason: a change of language always changes it, so no word outlives its language.

```tsx
export const UiWords = ({ children }: { children: ReactNode }) => {
  const { t, i18n } = useLingui();
  return (
    <I18nProvider
      locale={i18n.locale}
      catalog={{
        copyButton: {
          copied: t`Copied`,
          copy: t`Copy`,
          copyError: t`Not copied`,
        },
        action: {
          agentAsks: t`Does something that needs your yes`,
          agentPresses: (words) => t`Presses "${words}"`,
          error: t`Could not finish`,
          loading: t`Working`,
          success: t`Done`,
        },
      }}
    >
      {children}
    </I18nProvider>
  );
};
```

## Words we use

Take the word on the left; where a component says it itself, the right column names it.

| Use | Not | Where it is said |
| --- | --- | --- |
| Delete | Remove permanently | Alert dialog's and Hold button's examples |
| Keep it | Cancel, in a question before a step | Connect API key block |
| Not saved | Error saving | Button's press that takes time |
| Could not save | Error | Field, Inline edit, Image upload |
| Try again | Retry | Message, Data table, Field, File upload |
| Thinking | Loading | Reasoning |
| You are offline. Your changes are kept on this device and sent when you are back online. | Saved here and send when you are back | Toast's example |
| Loading the sound | Loading | Audio player |
| Loading the page | Loading | Pagination |
| No sources | 0 sources | Sources |
| Show less (text) | Show fewer (text) | Code block |
| Send answer, Send | Submit | Questionnaire, Prompt input |
| Sources | References | Sources |
| You | The user | Message |
| Choose | Select | Data table, Date picker, Combobox, File upload |
| Undo | Revert | Data table, Diff viewer |
| Sign in | Log in | Brand icon |

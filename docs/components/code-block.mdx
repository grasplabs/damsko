## Basic usage

A `CodeBlock` in its `language`, a `CodeBlockHeader` with its `CodeBlockTitle` (the language's name) and `CodeBlockActions` holding the `CodeBlockCopyButton`, and the code as text in `CodeBlockContent`, which highlights it. A region named by its language; `lineNumbers` numbers the lines.

<Stage path="code-block/basic" label="Basic usage" />

## A title and highlighted lines

A title in `CodeBlockTitle`, such as a file name, heads it beside the language and names the region. To mark lines, give `CodeBlockContent` its lines as `CodeBlockLine`s: `useHighlightedCode` gives them highlighted, and `variant="highlighted"` washes the lines an answer is about in mint, with a bar.

<Stage path="code-block/file" label="A title and highlighted lines" />

## A change

`variant="added"` and `variant="removed"` wash a line in the diff's colours, a bar at its start in each.

<Stage path="code-block/diff" label="A change" />

## More beside Copy

More in `CodeBlockActions` before the copy button, in the order given: here `CodeBlockDownloadButton`, which saves the code as a file (`file.ts` by the language's extension, or the `filename` given); any other is a ghost icon Button the copy button's size (`icon-sm`). Both wait while the code is written. On a phone they stay in the header and the title gives way.

<Stage path="code-block/actions" label="More beside Copy" />

## No header

`CodeBlockActions` straight in the `CodeBlock` stand over the code's corner, shown under a pointer or focus, and always on a touch screen. `aria-label` names the block.

<Stage path="code-block/floating" label="No header" />

## Long code

Past `maxLines` on `CodeBlockContent`, 18 by default, it is folded under Show more, with a fade where it is cut. Show more is a Button: Enter or Space opens it, and again folds it.

<Stage path="code-block/long" label="Long code" />

## Very long output

Folded, only the lines that show are drawn; opened, at most the first 2,000 are, and a line under them says how many more there are. Copy takes all of it. Where every line must be read (what an action will send), `maxLines={false}` never folds and draws every line, however many: only for code whose length the product knows is bounded. Markdown never lifts the cap, even with `codeMaxLines={false}`, since a model's output has no bound.

## While it is written

`streaming` on the `CodeBlock`: the title says it is being written, copying waits, and the code grows in place, read again at most once a frame however fast it comes. `showStreamingIndicator` adds a Spinner beside the words.

<Stage path="code-block/streaming" label="While it is written" />

## Any code

The code is coloured on the page by [@pierre/highlights](https://www.npmjs.com/package/@pierre/highlights): lexers written by hand and compiled to WebAssembly, with no regular expressions, so reading a line takes time that grows with the line and nothing else. 3,000 lines of TypeScript take about a millisecond, and text that held regular-expression highlighters for seconds (a string of 50,000 characters that never ends, thousands of nested template strings) takes a few. Nothing of them loads with the page: the package's core (22 KB gzipped, with its emitter) and a language's lexer (2 to 11 KB) load the first time a block in that language is drawn, and each other lexer the first time a block in its language is; until then, and before the page's script runs, the code is plain. A lexer that does not load leaves its language plain. Drawing the colours is what takes time now, as each coloured run is an element: a line of 250 characters or more (minified code, generated data) is drawn as its text, and a block whose lines would be more than 5,000 coloured runs, some 1,500 lines of ordinary code, is drawn plain, all of it. So the 18 lines a folded block shows are always coloured, whatever they hold, and opened with Show more it is weighed again. While it is written, each line is coloured once its newline comes; the line still being written is plain until then, and a line already coloured is never drawn again.

<Stage path="code-block/any" label="Any code" />

## Content Security Policy

The lexers are WebAssembly, compiled from scripts of their own that the app's build writes beside its other scripts (the core, and one for each language), each module inside its script: nothing else is fetched and no worker is started. A policy that names `script-src` (or a `default-src` it falls back to) adds `'wasm-unsafe-eval'`, which allows WebAssembly and nothing else; `worker-src` needs nothing (Get started, Allow CodeBlock's WebAssembly):

```text
Content-Security-Policy: script-src 'self' 'wasm-unsafe-eval'
```

Without it, and in a browser without WebAssembly, every block is plain, whole and readable, and nothing is said: the page reports the refusal to the policy once, and the console stays empty.

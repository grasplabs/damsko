## An answer

Headings, lists, a table (Table, scrolling sideways in its own box), code in a sentence and in a fence (CodeBlock), a quote and a link (Link), in the interface's own type.

<Stage path="markdown/answer" label="An answer" />

## While it is written

`streaming`: the block still being written is drawn as what it will be (remend makes it whole): bold is bold from its first letter, code is code, and a link or a picture still being written is its words. A table comes with its row of dashes and each row once its line has ended; an open fence is code in a CodeBlock that says it is being written. A bare address is its words until the space after it, and only a whole address is handed to the host. Each new word fades in, at once with reduced motion; pacing the words is the message's job. A finished block is read once and drawn once, so a long answer costs no more to draw at its end than at its start.

## Cut off

Once `streaming` turns false, the answer is drawn as written, the same as when the page is opened again. An answer stopped part way ends tidily with `truncated`: its end is made whole as while it streams, so no raw mark and no half link shows. Set it when the stream is stopped, and for a cut answer drawn later, from history.

<Stage path="markdown/cut" live label="Cut off" />

## Headings

A `#` heading is an `h1`, `##` an `h2`, and so on. Under a page's own title, `headingLevel` starts them lower, so the page's outline never skips or repeats a level; their look stays the answer's own.

<Stage path="markdown/headings" label="Headings" />

## Untrusted text

Its links may come from a page the agent read. Raw HTML is text, never HTML; a link of Markdown's own leads only to http, https, mailto, tel or a path on this site; a picture is never loaded. A task's box and a note's mark stay as written, and a note is drawn where it is written. micromark weighs each emphasis or link mark of a paragraph against those before it, so a paragraph with more than 1,000 is drawn without them, as words, and nesting deeper than the parser can follow is drawn as its words: no answer, however hostile, takes long to draw.

## The host's links

Markdown knows no router and no citation. `renderLink` draws every link and picture, any scheme, before the filter, and gets its address as written, its scheme, its title, its words and its `type` (`link`, `autolink` or `image`); undefined leaves it to Markdown. Here a link out asks first, and a path inside the product goes through the product's router as Link's child (`asChild`). A part around Markdown can draw links for every Markdown inside it with `MarkdownLinkProvider`: here the product's `cite:` links are numbered chips. The page's own `renderLink` is asked first. While an answer is written, no part of the host's is handed half an address: a link or picture still being written is its words until what follows can no longer make it anything else (its closing mark with nothing still open before it, or for a bare address the space after it), and then the host's link in their place.

```tsx
<MarkdownLinkProvider
  renderLink={(link) =>
    link.scheme === "cite" ? <Citation href={link.href} /> : undefined
  }
>
  <Markdown
    renderLink={(link) =>
      link.href.startsWith("/") ? (
        <Link asChild>
          <RouterLink to={link.href}>{link.children}</RouterLink>
        </Link>
      ) : undefined
    }
  >
    {answer}
  </Markdown>
</MarkdownLinkProvider>
```

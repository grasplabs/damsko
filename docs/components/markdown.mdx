## An answer

Headings, lists, a table (Table, scrolling sideways in its own box), code in a sentence and in a fence (CodeBlock), a quote and a link (Link), in the interface's own type.

<Stage path="markdown/answer" label="An answer" />

## While it is written

`streaming`: what is half-written at the end is drawn as what it will be. A table is a table from its head, code shows as it comes in a CodeBlock that says it is being written, a link still being written is its words with its arrow's room kept, and bold is bold from its first letter. Nothing flickers or re-flows when a mark closes. The words come as they are given: pacing them is the message's job. A screen reader hears each block once it is finished, never each word; `live="off"` keeps it silent, for words beside the answer that another part already says (Reasoning's thoughts).

## Cut off

An answer stopped part way ends tidily: once `streaming` turns false, a link still being written at its end goes and bold or code left open is closed, so no raw mark shows. A cut answer drawn later, from history, does the same with `truncated`.

<Stage path="markdown/cut" live label="Cut off" />

## Single line breaks

A model often writes short lines (a label and its value, a list of steps) with one newline between them. As CommonMark has it, one newline is a space, so those lines run together. `softBreaks="line"` draws every single newline as a line break; `auto` breaks only a paragraph of short lines (two or more, each under 60 characters, or each "Label: value"), so a paragraph the model wrapped by hand still reads as one. While the answer streams, a short line breaks as its newline comes, and no lines drawn apart run together again.

<Stage path="markdown/line-breaks" label="Single line breaks" />

## Headings

A `#` heading is an `h1`, `##` an `h2`, and so on. Under a page's own title, `headingLevel` starts them lower, so the page's outline never skips or repeats a level; their look stays the answer's own.

<Stage path="markdown/headings" label="Headings" />

## Tasks and rules

Task lists are Checkbox's box, read only, each said as done or not done; a rule is a Separator.

<Stage path="markdown/tasks" label="Tasks and rules" />

## Sections that fold

A section written as GitHub's `<details>` with a `<summary>` line is drawn as a section: its summary a button, its body under it, closed until it is opened. Only that form: any other HTML stays text.

<Stage path="markdown/sections" label="Sections that fold" />

## Untrusted text

Its links may come from a page the agent read. Raw HTML is text, never HTML, and a link of Markdown's own leads only to http, https or mailto; a picture is never loaded. A paragraph, heading or table cell over 8,000 characters is drawn as plain text, and so is one with more than 128 marks (the characters that start or end a link, emphasis, code or a tag) once such paragraphs have spent the answer's budget of 6,000,000, each its marks squared: an ordinary answer keeps every mark at any length, and no answer, however hostile, takes long to draw. A single block of more than 64 lines (a list, a table, a quote) spends its lines squared from a budget of 8,000,000, and its lines past that are drawn as plain lines: a list of 2,800 items is a list, and one of 100,000 is a list for its first 2,800.

## The host's links

Markdown knows no router and no citation. `renderLink` draws every link and picture, any scheme, before the filter, and gets its address as written, its scheme, its title, its words and its `type` (`link`, `autolink` or `image`); undefined leaves it to Markdown. Here a link out asks first, and a path inside the product goes through the product's router as Link's child (`asChild`). A part around Markdown can draw links for every Markdown inside it with `MarkdownLinkProvider`: here the product's `cite:` links are numbered chips. The page's own `renderLink` is asked first. While an answer is written, a link inside a provider is held back until its address has arrived, so a citation never shows first as words.

```tsx
<MarkdownLinkProvider
  renderLink={(link) =>
    link.scheme === "cite" ? <Citation href={link.href} /> : undefined
  }
>
  <Markdown
    renderLink={(link) =>
      link.href.startsWith("/") ? (
        <Link asChild>
          <RouterLink to={link.href}>{link.children}</RouterLink>
        </Link>
      ) : undefined
    }
  >
    {answer}
  </Markdown>
</MarkdownLinkProvider>
```

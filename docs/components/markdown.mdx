## An answer

Headings, lists, a table (Table, scrolling sideways in its own box), code in a sentence and in a fence (CodeBlock), a quote and a link (Link), in the interface's own type.

<Stage path="markdown/answer" label="An answer" />

## While it is written

`streaming`: what is drawn and when follows Streamdown, our parts and safety rules drawing it. The block still being written is drawn as what it will be (remend makes it whole): bold is bold from its first letter, code is code, a link still being written is its words and a picture nothing yet. A table comes with its row of dashes, then each row as it is written; an open fence is code in a CodeBlock that says it is being written. A bare address is its words until the space after it, and only a whole address is handed to the host; while a link of Markdown's own is still being written, the room its arrow will take is kept, so nothing after it moves when it is whole. A task's box waits for the words after it, and a section that folds is one from its whole summary line. A reference to a link and a note's mark are as written until their definition has come (for a link, once the block that holds it is finished, so its address can no longer change), then the link or the note's number. Each new word comes whole and fades in once (each character in Chinese, Japanese and Korean), never typing itself out: the word at the very end, in prose, a cell or code, waits for the space after it, or for a quarter second once nothing more comes, and a run of more than 32 characters (an address, minified code) comes 32 at a time, past 256 as it comes. With reduced motion nothing fades and nothing waits: the words show as they arrive. A link's words do not fade, as they move into the link when it is whole; a mark of emphasis or code at the very end waits for its words, and a closing fence for its last mark; pacing the words is the message's job. A finished block is read once and drawn once, so a long answer costs no more to draw at its end than at its start. A screen reader hears each block once it is finished, never each word: the blocks already finished when it is first drawn are said then, once, and an answer first drawn whole (opened from history) is not said at all; `live="off"` keeps it silent, for words beside the answer that another part already says (Reasoning's thoughts).

## Tables

A cell's words wrap as a sentence's do, its column's name too (as GitHub draws them), so a table fits the answer's column, on a phone as well; a column the Markdown sets to the right (`--:`, figures) stays on one line, code in a cell may break, and a model's `<br>` in a cell is a line break there. Each column keeps the narrowest a column may be (64 px), so a table that cannot fit (many columns, a long address) scrolls sideways in its own box: the edge with more beyond it fades, and the box is a region named by the table that Tab reaches and the arrow keys move. While the answer is written its columns share the width evenly, each at least that wide, so no row that comes moves the ones above it.

<Stage path="markdown/tables" label="Tables" />

A table has Copy and Download over it, as Streamdown's tables have: Copy takes its cells' words as Markdown, CSV or TSV, Download saves them as `table.csv` or `table.md`. As Markdown, each cell reads back as the same cell: code, emphasis, links, pictures, notes' marks and maths as written (a link or a picture written by reference with its address, since the table is copied without the answer's definitions), and a picture's words in CSV and TSV are its alt text. A cell that starts like a formula (`=`, `+`, `-`, `@`) is kept as words in CSV and TSV, as DataTable's export keeps it, by an apostrophe before it; a figure such as `-12` or `+3.5%` is left as it is. Both wait while the answer is written, and a caller's own `table` draws neither.

## Code

Fenced code is a CodeBlock in the fence's language: coloured by CodeBlock's lexers, plain until they have loaded, the language's name over it, its lines numbered (from N with `startLine=N` after the language, not at all with `noLineNumbers`, as Streamdown reads them), and Download (as `file.ts`, by the language's extension, else `file.txt`) and Copy beside it. While the answer is written both wait, as a chat's do, and the code grows in place: each line is coloured once its newline comes, read once, and the line still being written is plain, so no chunk colours the whole block again.

## Maths

A formula between two dollars, as Streamdown reads one: `$$x^2$$` in a sentence, and lines of their own between `$$` and `$$`; one dollar is a dollar (`$5`). KaTeX draws it as MathML, which the browser lays out in its own maths font, a size up as KaTeX's own styles set it (1.21em), so its x-height meets the words' round it and it sits on their baseline, in a sentence, a heading, a list or a table; KaTeX is loaded only when a formula is drawn: a page without maths loads none of it, and until it has loaded, and without script, a formula is its TeX. KaTeX builds the formula's nodes itself and never reads HTML from it; no command in it can lead anywhere, load anything, or add a class or a style, and one it cannot read is shown as its TeX, muted, as Streamdown shows it. While a formula is written it is drawn as far as it goes, closed as remend closes it. A formula longer than 4,000 characters stays its TeX (the browser lays out MathML on the page, and 100 KB of it takes seconds), and no rule, space or box in one is larger than 10em; one in a sentence is cut at ten lines' height (a matrix of a thousand rows would be thousands of pixels tall). Under a Content Security Policy KaTeX is a script of the page's own (`script-src 'self'`); the muted colour of a formula it cannot read is an inline style, so without `style-src 'unsafe-inline'` that formula is its TeX in the text's colour.

## Diagrams

A fence in `mermaid` is its diagram once the fence is closed and it comes near the screen, drawn by [Pele](https://pele.run) (MIT), which reads Mermaid's syntax and draws every one of its diagram types, shown below. Pele draws the diagram as a string of SVG, with no DOM, no frame and no worker, and fetches nothing. It lays the diagram out for the room it has: in a column narrower than 640px a wide one is laid out upright (a flowchart left to right turns top to bottom), so its words stay readable rather than shrunk to fit. It loads only when a diagram is drawn, a page without one loads none of it: first its core, then the diagram's type, each a chunk of its own, so a page of flowcharts loads only the flowchart's. While Pele loads and draws it, the diagram is busy (`aria-busy`) and shows its code; while the fence is written, and until it has drawn, it is its code.

What keeps it safe, in order. A fence is weighed first, as written and with its character references read (`&sol;`, `#40;`): one that holds any way to an address (`url(`, `image-set(`, `img`, `//`, `@import` or a backslash, in any case), or a sequence diagram's `properties` or `details` statement, is its code and never reaches Pele. A diagram with a web address in a label is code too, the price of weighing its words rather than each diagram type's reading of them. So is one of more than 1,500 characters, 40 lines that hold something (a `;` ends one too, and a line ended by both counts once) or 100 parts (its words outside its labels). Pele has no time limit of its own; at these bounds the slowest fence of any type measured draws in under 150 ms on a CPU slowed eight times, and most in under 30 ms. Then Pele draws it with its links and pictures off and its own limits on (the source at 1,500 characters, its output and its edges at its defaults); its labels are SVG text, never HTML. What it draws is read as SVG and holds only SVG's own elements and the drawing's own styles: no link, no handler, no picture and nothing that points outside the drawing.

Once it has settled, its frame says whether it is drawn and, when it is its code, why, so a host's test waits for that rather than for a fixed time: `data-diagram` (not there while it is drawn) is `drawn`, `skipped:limit` or `skipped:source` (not given to Pele, by design), or `failed:load`, `failed:syntax`, `failed:render` or `failed:output` (Pele was asked and did not draw it, past one of its own limits too; a failure is said once with `console.debug`, never with the fence's words). A chunk that did not load is asked for again by the next diagram. A diagram with an `accTitle` is named by it, else as a Mermaid diagram, with its code as its description.

It is drawn in the design's look through Pele's CSS variables: nodes on the muted surface with a mint edge and the ink's words, edges in the muted words' colour, charts in the chart tones, the page's fonts (its words measured in them) and corners. The tokens resolve where the diagram stands, so it follows light, dark or a band of its own colour scheme as the page does, in place and without being drawn again, and takes the system's colours under forced colours. Saved as SVG or PNG it keeps the look it has when it is saved, on the page's background. Beside it, as Streamdown has them: Download (the drawing as SVG or PNG, or its code as `diagram.mmd`), Copy and full screen, all waiting while the answer is written; under it, zoom in, zoom out and back, and a drag or the arrow keys move it (a finger scrolls the answer past it, and moves it only in full screen). Under a Content Security Policy, Pele is scripts of the page's own (`script-src 'self'`, loaded only when a diagram is drawn) and needs no frame, worker, connection or picture of its own; the drawing carries its styles in `style` attributes (`style-src 'unsafe-inline'`) and the PNG is drawn from a `data:` picture (`img-src data:`).

## Cut off

Once `streaming` turns false, the answer is drawn as written, the same as when the page is opened again. An answer stopped part way ends tidily with `truncated`: its end is made whole as while it streams, so no raw mark and no half link shows. Set it when the stream is stopped, and for a cut answer drawn later, from history.

## Single line breaks

A model often writes short lines (a label and its value, a list of steps) with one newline between them. As CommonMark has it, one newline is a space, so those lines run together. `softBreaks` draws every single newline as a line break, for answers written that way; a paragraph the model wrapped by hand then breaks where it was wrapped.

## Headings

A `#` heading is an `h1`, `##` an `h2`, and so on. Under a page's own title, `headingLevel` starts them lower, so the page's outline never skips or repeats a level; their look stays the answer's own.

## Tasks and rules

Task lists are Checkbox's box, read only, each said as done or not done; a rule is a Separator.

## Footnotes

A note's mark (`[^1]`) is a number up high, numbered by where it first stands, leading to its note in a list at the foot; each note leads back to each of its marks (`↩`, `↩²`). A mark whose note is never written is shown as written, and a note no mark refers to is not drawn.

<Stage path="markdown/footnotes" label="Footnotes" />

## Alerts

A quote whose first line is only one of GitHub's marks, `[!NOTE]`, `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]` or `[!CAUTION]` (in any case), is an Alert of that meaning (info, success, the plain one, warning, destructive), titled from the I18nProvider (`markdown.alerts`), with the rest of the quote as its words. It is part of the answer, never said again as it appears. As GitHub reads one, any other mark, words on the mark's line or a mark with nothing after it leave a quote; unlike GitHub, an alert in a list or in another quote is one too. While written, the mark alone already draws the alert, so `[!NOTE]` never shows.

<Stage path="markdown/alerts" label="Alerts" />

## Right to left

Each paragraph, heading, list item, quote and table cell takes the direction of its own words (`dir="auto"`, as GitHub sets it): one in Arabic or Hebrew runs right to left, a list item's marker and a quote's bar on its right, beside blocks in English that run left to right. A quote's paragraphs take the quote's direction. Code, in a sentence or fenced, and formulas always run left to right.

<Stage path="markdown/right-to-left" label="Right to left" />

## Sections that fold

A section written as GitHub's `<details>` with a `<summary>` line is drawn as a section: its summary a button, its body under it, closed until it is opened (`<details open>` stands open). Only that form: any other tag is dropped, its words kept.

## Untrusted text

Its links may come from a page the agent read. HTML is never drawn: a tag outside code (an open or closing tag, a comment) is dropped, what it holds and what follows it is read as Markdown (a tool's tag on a line of its own over a list leaves the list, links and all), and nothing from it ever becomes an element; `<br>` is a line break. Only `<details>` with its `<summary>` line is read, as a section. A tag still being written waits for its `>`. Code, in a sentence or fenced, keeps tags as written, and an address in angle brackets (`<https://…>`, `<a@example.com>`) is a link. As in Streamdown, a generic written outside code loses its tag: `Array<string>` shows as `Array`, so write it as code. `a < b`, `<3` and `<-` are words. A link of Markdown's own leads only to http, https, mailto, tel (a phone number, which a browser only offers to call) or a path on this site; a picture is never loaded. micromark weighs each emphasis or link mark of a paragraph against those before it, so a paragraph with more than 1,000, or a block with more than 5,000 in all (fenced code aside), is drawn without them, as words. A bare address is read again from each place one may start to the end of its word, so in a block with a word of more than 1,000 characters (only a space, a tab or a line's end ends a word; fenced code aside), bare addresses are words; its emphasis and links stay. A list or quote nested deeper than 32 is drawn 32 deep (a quote written `>` with no space after it, at most 64); a paragraph of more than 1,000 lines goes on as another, and a list of more than 1,000 lines goes on as another at its next item, numbered on; a table draws, and reads, at most its first 1,000 rows, with a line under it that says how many more, and what ends the table (a heading, a quote, a list, a fence, a break) is drawn after it. While an answer is written, the block still being written is made whole by remend unless it holds more than 1,000 `[`, and read again as it grows: at once while that is quick, and once it takes long, only when four times its last read has passed, so reading takes at most a fifth of the time and new words still come about every 100 ms; past 1,000 words in that block, the words since its last read fade in as one. No answer, however hostile, takes long to draw. Fenced code draws at most its first 2,000 lines, and a line under them says how many more there are: `codeMaxLines={false}` only stops it folding, it never lifts that cap. Copy takes all of it.

## The host's links

Markdown knows no router and no citation. `renderLink` draws every link and picture, any scheme, before the filter, and gets its address as written, its scheme, its title, its words and its `type` (`link`, `autolink` or `image`); undefined leaves it to Markdown. Here a link out asks first, and a path inside the product goes through the product's router as Link's child (`asChild`). A part around Markdown can draw links for every Markdown inside it with `MarkdownLinkProvider`: here the product's `cite:` links are numbered chips. The page's own `renderLink` is asked first. While an answer is written, no part of the host's is handed half an address: a link or picture still being written is its words until what follows can no longer make it anything else (its closing mark with nothing still open before it, or for a bare address the space after it), and then the host's link in their place.

```tsx
<MarkdownLinkProvider
  renderLink={(link) =>
    link.scheme === "cite" ? <Citation href={link.href} /> : undefined
  }
>
  <Markdown
    renderLink={(link) =>
      link.href.startsWith("/") ? (
        <Link asChild>
          <RouterLink to={link.href}>{link.children}</RouterLink>
        </Link>
      ) : undefined
    }
  >
    {answer}
  </Markdown>
</MarkdownLinkProvider>
```

## Your own elements

`components` draws elements in Markdown's place, keyed by HTML element name (the keys react-markdown and Streamdown take, so a map written for them carries over): `a`, `blockquote`, `code`, `del`, `em`, `h1` to `h6`, `hr`, `img`, `li`, `ol`, `p`, `pre`, `strong`, `table`, `thead`, `tbody`, `tr`, `th`, `td` and `ul`. Each is given the element's own props (`dir="auto"` on a paragraph, heading, list item, quote and cell) and the syntax tree's `node`. The safe defaults hold: `a` gets only an address Markdown would lead to, whole, and `img` only a picture at an http or https address, whole: giving it chooses to load pictures. `code` draws code in a sentence and fenced code (`node.type` is `code`, `className` is `language-…`) in CodeBlock's place, so a fence can be a diagram or maths of the product's own. Task boxes, notes, sections and alerts stay Markdown's own. Here a link names its site and fenced code has no line numbers.

**`node` is internal.** It is the parser's syntax tree node (mdast), given so a part can tell what it draws, as `node.type` and a fence's `node.value` do here. Its shape is the parser's and changes when the parser does, and it holds the answer as written: its `url` is unchecked. Draw a link or a picture from the checked `href` and `src`, never from `node.url`.

```tsx
<Markdown
  components={{
    a: ({ href, children }) => (
      <ProductLink href={href}>{children}</ProductLink>
    ),
    code: ({ node, children }) =>
      node.type === "code" ? (
        <Diagram source={node.value} />
      ) : (
        <code>{children}</code>
      ),
  }}
>
  {answer}
</Markdown>
```

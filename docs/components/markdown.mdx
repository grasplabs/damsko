## An answer

Headings, lists, a table (Table, scrolling sideways in its own box), code in a sentence and in a fence (CodeBlock), a quote and a link (Link), in the interface's own type.

<Stage path="markdown/answer" label="An answer" />

## While it is written

`streaming`: what is half-written at the end is drawn as what it will be, and what was shown is only ever added to, but in two places: when a link's definition arrives, the references to it, shown as written until then, become the link; and when an answer ends without a note it refers to, that note's mark, a number while written, is shown as written. A table is a table from its row of dashes, code shows as it comes in a CodeBlock that says it is being written, and bold is bold from its first letter. A link, a picture or a bare address is its words (with a link's arrow room kept) until what follows can no longer make it anything else: its closing mark with nothing still open before it (a bracket, a tag, code, another link), and for a bare address the space after it. Then it is the link in their place, and only then is its address handed to the host. What is only the start of a mark waits for its words: a list's number, a task's box, a fence, a tag, a bracket that may open a link, a backslash, a character's name (`&am`). A note's mark shows its number at once: the number the whole answer gives it when every note it refers to arrives (a model writes its notes at the end). A note that never comes is shown as written once the answer is whole, and the notes after it then move up: `A[^1] B[^2]` with only `[^2]` written shows 1 and 2 while written, then `[^1]` and 1. A reference to a link is shown as written until its definition arrives, as it is should none come, and a section that folds is one from its summary. Nothing flickers or re-flows when a mark closes. The words come as they are given: pacing them is the message's job. A screen reader hears each block once it is finished, never each word; `live="off"` keeps it silent, for words beside the answer that another part already says (Reasoning's thoughts).

## Cut off

Once `streaming` turns false, the answer is drawn as written, the same as when the page is opened again. An answer stopped part way ends tidily with `truncated`: a link still being written at its end goes and bold or code left open is closed, so no raw mark shows. Set it when the stream is stopped, and for a cut answer drawn later, from history.

<Stage path="markdown/cut" live label="Cut off" />

## Single line breaks

A model often writes short lines (a label and its value, a list of steps) with one newline between them. As CommonMark has it, one newline is a space, so those lines run together. `softBreaks="line"` draws every single newline as a line break; `auto` breaks only a paragraph of short lines (two or more, each under 60 characters, or each "Label: value"), so a paragraph the model wrapped by hand still reads as one. While the answer streams, a short line breaks as its newline comes, and no lines drawn apart run together again.

## Headings

A `#` heading is an `h1`, `##` an `h2`, and so on. Under a page's own title, `headingLevel` starts them lower, so the page's outline never skips or repeats a level; their look stays the answer's own.

## Sections that fold

A section written as GitHub's `<details>` with a `<summary>` line is drawn as a section: its summary a button, its body under it, closed until it is opened. Only that form: any other HTML stays text.

## Untrusted text

Its links may come from a page the agent read. Raw HTML is text, never HTML, and a link of Markdown's own leads only to http, https or mailto; a picture is never loaded. A paragraph, heading or table cell over 8,000 characters is drawn as plain text, and so is one with more than 128 marks (the characters that start or end a link, emphasis, code or a tag) once such paragraphs have spent the answer's budget of 1,500,000, each its marks squared: an ordinary answer keeps every mark at any length, and no answer, however hostile, takes long to draw. A single block of more than 64 lines (a list, a table, a quote, notes one under the other; code, HTML and definitions of links do not count) spends its lines squared from a budget of 2,000,000, a line that opens more than one quote or list counting as one for each, and its lines past that are drawn as plain lines: a list of 1,400 items is a list, and one of 100,000 is a list for its first 1,400. The budgets are the answer's, not a moment's: what the blocks already drawn spent counts for those that follow while it streams, and once it ends the answer is read whole, once, with the same budgets as when the page is opened again, so both draw the same. A table's row draws its own cells, at most as many as its head, so a wide head over many short rows draws no more than was written. While an answer is written, the block being written is read with at most 128 of the names of links and notes that the blocks before it define; past those, a reference is its words until the answer is whole. Fenced code draws at most its first 2,000 lines, and a line under them says how many more there are: `codeMaxLines={false}` only stops it folding, it never lifts that cap. Copy takes all of it.

## The host's links

Markdown knows no router and no citation. `renderLink` draws every link and picture, any scheme, before the filter, and gets its address as written, its scheme, its title, its words and its `type` (`link`, `autolink` or `image`); undefined leaves it to Markdown. Here a link out asks first, and a path inside the product goes through the product's router as Link's child (`asChild`). A part around Markdown can draw links for every Markdown inside it with `MarkdownLinkProvider`: here the product's `cite:` links are numbered chips. The page's own `renderLink` is asked first. While an answer is written, no part of the host's is handed half an address: a link or picture still being written is its words until what follows can no longer make it anything else (its closing mark with nothing still open before it, or for a bare address the space after it), and then the host's link in their place.

```tsx
<MarkdownLinkProvider
  renderLink={(link) =>
    link.scheme === "cite" ? <Citation href={link.href} /> : undefined
  }
>
  <Markdown
    renderLink={(link) =>
      link.href.startsWith("/") ? (
        <Link asChild>
          <RouterLink to={link.href}>{link.children}</RouterLink>
        </Link>
      ) : undefined
    }
  >
    {answer}
  </Markdown>
</MarkdownLinkProvider>
```

## Your own elements

`components` draws elements in Markdown's place, keyed by HTML element name (the keys react-markdown and Streamdown take, so a map written for them carries over): `a`, `blockquote`, `code`, `del`, `em`, `h1` to `h6`, `hr`, `img`, `li`, `ol`, `p`, `pre`, `strong`, `table`, `thead`, `tbody`, `tr`, `th`, `td` and `ul`. Each is given the element's own props and the syntax tree's `node`. The safe defaults hold: `a` gets only a link Markdown would draw (http, https or mailto, its address whole), and `img` only a picture at an http or https address, once that address is whole: giving it chooses to load pictures. `code` draws code in a sentence and fenced code (`node.type` is `code`, `className` is `language-…`) in CodeBlock's place, so a fence can be a diagram or maths of the product's own. Here a link names its site and fenced code has no line numbers.

**`node` is internal.** It is the parser's syntax tree node (mdast), given so a part can tell what it draws, as `node.type` and a fence's `node.value` do here. Its shape is the parser's and changes when the parser does, and it holds the answer as written: its `url` and its raw HTML are unchecked. Draw a link or a picture from the checked `href` and `src`, never from `node.url`.

```tsx
<Markdown
  components={{
    a: ({ href, children }) => (
      <ProductLink href={href}>{children}</ProductLink>
    ),
    code: ({ node, children }) =>
      node.type === "code" ? (
        <Diagram source={node.value} />
      ) : (
        <code>{children}</code>
      ),
  }}
>
  {answer}
</Markdown>
```

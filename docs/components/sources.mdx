## Under an answer

Built on [Trace](/components/trace): the trigger is a TraceLine whose title is a pile, the first sources' marks overlapping, then the count, `count` on `SourcesTrigger`; each source is a TraceLine in a link, beside its mark's tile, where it lives under its title. A source on another site shows the host its address names, read from the checked address, never words of the caller's: `origin` says where a source lives only when its address names no host. Press it to open the list, and again to fold it. From an AI SDK message, the sources are its `source-url` parts, each address once: the agent may cite a page twice.

## Opened by the page

`onOpen` tells the page a source was opened. A source with an `href` stays a link and goes there too; one without is a button that only runs `onOpen`. An address comes from a model or a tool, so it is checked as a link in Markdown is: http, https, mailto or a path on this site leads there, and any other (`javascript:`, `data:`, `//elsewhere`) leaves the title as words.

`index` is the number the answer's citations give a source: it stands after the title and is said with it, so it holds whatever order the list is in. `quote` is the passage the answer used, up to two lines under where it lives; a source that cannot be opened shows none. The head here, its count, an order switch and a fold, is the page's own composition above `SourcesContent`.

## Locked and gone

`access="locked"` says the source is there but not for this person; `access="gone"` that it could not be opened. Neither is a link, and the mark goes quieter.

<Stage path="sources/access" label="Locked and gone" />

## Your marks

SourceIcon holds whatever you map a source to: an icon for a file, a site's own small icon, a person's portrait. In the trigger it is smaller and overlaps the one before.

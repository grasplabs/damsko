## Conversation

A `Message` is the row; its `MessageContent` is the column that holds the surface. The person's message stands at the end (`align="end"`), its words in a muted [Bubble](/components/bubble); the assistant's is plain words across the column. Each message is named by who wrote it (You at the end, Assistant at the start), so a screen reader tells the two apart by more than their side; `aria-label` names it otherwise. `MessageFooter` holds the time, which shows where a pointer hovers the message or the focus is in it.

<Stage path="message/conversation" label="Conversation" />

## An answer in Markdown

`MessageResponse` draws the answer from Markdown: lists, tables and code. Copy copies the Markdown source as it was written.

<Stage path="message/chat-text" label="An answer in Markdown" />

## Streaming

With `status="streaming"`, the words come in a word at a time at a steady pace, however unevenly the chunks arrive, each fading in as it is shown, and what is half-written is drawn whole: Markdown's [Word by word](/components/markdown#word-by-word), which `animated` sets (`word`, `character`, or `false` for the words as they come). With reduced motion they are drawn as they arrive. When the stream ends, what is left runs out within 400ms. Its actions keep their room while it is written, unseen, so the end moves nothing. Give it the whole answer so far each time more arrives; the pace is the browser's, so a server need not smooth its stream.

<Stage path="message/streaming" label="Streaming" />

## Failed

`MessageError` says what did not happen, and Try again asks once more. The answer is written again in place, the focus stays in the message, and "Answer ready" is said once.

<Stage path="message/failed" label="Failed" />

## Stopped

Stopped part way, the answer keeps the words it had written, says Stopped under them, and still offers its actions.

<Stage path="message/stopped" live label="Stopped" />

## Actions

`MessageActions` is a named row under the surface: a `CopyButton` first, then `MessageAction`s, each a ghost icon button named by its `aria-label`, with a tooltip. A rating given stays pressed. The person's message can be edited.

<Stage path="message/actions" label="Actions" />

## Avatar

`MessageAvatar` stands beside the surface, level with its foot, on the message's own side.

<Stage path="message/avatar" label="Avatar" />

## A group

`MessageGroup` stacks consecutive messages from one writer. An empty `MessageAvatar` keeps the room of the avatar beside the ones before the last.

<Stage path="message/group" label="A group" />

## Header and footer

`MessageHeader` names who wrote it, above the surface; `MessageFooter` says when it was sent or whether it was read, under it.

## With a prompt input

One chat state drives both. PromptInput's `status` is the AI SDK's own (`ready`, `submitted`, `streaming`, `error`), and Message's describes one answer (`thinking`, `streaming`, `done`, `stopped`, `error`), so the latest answer's is read from it: `submitted` is `thinking`, `streaming` is `streaming`, `ready` is `done` (or `stopped` once the person stopped it), `error` is `error`. Every earlier answer is `done`.

```tsx
const { messages, status, sendMessage, stop } = useChat();
const [stopped, setStopped] = useState(false);
const answer: Record<ChatStatus, MessageStatus> = {
  submitted: "thinking",
  streaming: "streaming",
  ready: stopped ? "stopped" : "done",
  error: "error",
};

{
  messages.map((message, index) => (
    <Message
      key={message.id}
      align={message.role === "user" ? "end" : "start"}
      status={index === messages.length - 1 ? answer[status] : "done"}
    >
      …
    </Message>
  ));
}
<PromptInput
  status={status}
  onSubmit={({ text }) => {
    setStopped(false);
    // Not returned: it settles only once the whole answer has come.
    void sendMessage({ text });
  }}
>
  …
  <PromptInputSubmit
    onStop={() => {
      setStopped(true);
      void stop();
    }}
  />
</PromptInput>;
```

## Loading

`MessageSkeleton` is a message's shape while it loads, at the message's own widths: a muted Bubble at the end (`align="end"`), or the assistant's lines. Put them in a Message scroller with `loading`, which says once what is loading.

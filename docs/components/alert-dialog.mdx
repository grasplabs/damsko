## Basic usage

The title names the thing, the description says what is lost, and focus starts on the safe answer. The trigger is a plain wrapper: `asChild` hands its behaviour to a Button. `AlertDialogCancel` is the safe answer, an outline Button, as shadcn draws it; `AlertDialogAction` is the one action, and closes it with its `value`.

<Stage path="alert-dialog/basic" live label="Basic usage" />

## With work that can fail

Work before it closes is a Button in the footer whose `onClick` returns a Promise, as in a Dialog. While it works the alert dialog holds, and Escape waits: its `onOpenChange` cancels the close. When it fails, the Button says so and the alert dialog stays open.

<Stage path="alert-dialog/failed" label="With work that can fail" />

## Confirm without danger

Grave but deleting nothing: the action is `default`, not `destructive`, and still repeats the verb.

<Stage path="alert-dialog/confirm" label="Confirm without danger" />

## Long description

It wraps, and past the window's height only the description scrolls: a region named by the title, so the keys scroll it too.

<Stage path="alert-dialog/long-description" label="Long description" />

## With Cancel

Given no words, `AlertDialogCancel` says the I18nProvider's `alertDialog.cancel`: Cancel. Put it first, so focus starts on it.

<Stage path="alert-dialog/cancel" label="With Cancel" />

## On a phone

Under 640px it is a sheet along the bottom, and its answers share the line under the thumb. Nothing to set: the window's width decides.

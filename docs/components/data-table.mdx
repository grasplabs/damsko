## Basic usage

Press a column's name to sort by it; the search keeps the rows that hold its words.

<Stage path="data-table/basic" label="Basic usage" />

## Choosing rows

A checkbox on each row, one in the head for every row shown, and a count.

<Stage path="data-table/selectable" label="Choosing rows" />

## Columns

The View menu hides columns (`columnVisibilityFeature`); each column's menu pins, moves and hides it (`columnPinningFeature`, `columnOrderingFeature`). Its handle resizes it by pointer or arrow keys (`columnResizingFeature`).

<Stage path="data-table/columns" label="Columns" />

## Acting on rows

A bulk action's `severity` picks how it is confirmed: Archive (`undoable`) is undone from its toast; Delete (`grave`) asks first; a `moderate` one is held to confirm. A row opens to its summary (`rowExpandingFeature` with `renderDetailPanel`), and `filterable` narrows the rows by one condition. The toasts go to the page's one `<Toaster />` (the shared `toast`), so the page needs one at its root; a host that keeps its own queue passes it as `toaster`, as this example does.

<Stage path="data-table/rows" label="Acting on rows" />

## A row that opens a page

`getRowHref` makes each row's name a real link to its page, drawn as the cell's own words on the column's line (no control padding; a long name wraps at the start). The whole row is its press area; the checkbox, the row's menu and a column marked `control` stay their own. Tab stops once on each name, Enter follows it, and the row takes the ring. With scripts off it still works; it opens in a new tab as any link does.

<Stage path="data-table/opens-page" label="A row that opens a page" />

## A row that opens, its first column held

With `stickyFirstColumn` the held name cell is the row's press area, not the whole row: a held cell is a box of its own, which the name's press area cannot reach past. The name opens the page as in any row; the other cells do not.

<Stage
  path="data-table/opens-held"
  label="A row that opens, its first column held"
/>

## A row that opens a panel

`onRowClick` makes the name a button that opens something on the page. `isRowActive` marks the row open now: said as current, with a quiet fill of its own, apart from the selection.

<Stage path="data-table/opens-panel" label="A row that opens a panel" />

## Members

A person in the lead cell is the page's own `cell`; `control` on the role's column keeps the row's height with a Select in it. `skeleton: "person"` makes a column wait in a person's shape while the table loads.

<Stage path="data-table/members" label="Members" />

## A row's state

`getRowStatus` draws a row's state over the whole row, never cell by cell: `pending` (someone invited, not yet here) fades from the row's start to its end, and `removed` greys it. Each is said after the row's first words too, and the row's actions stay whole and usable. Right to left, the fade runs the other way.

<Stage path="data-table/members-status" label="A row's state" />

## Columns that make room

`hideBelow` on a column takes it away, head and cells, when the table's own box is narrower than the `sm` (40rem) or `md` (48rem) breakpoint. It answers to the table's box, not the window, so a table in a narrow panel makes room too. A column you hide must never be the only place its fact lives: keep it in the row or on the row's own page, and never hide the first column, which names the row.

`description` on a column puts an info mark beside its name, whose tooltip says more about the column (here, what each role may do). The name stays `header`, which sorting and the column's menu say.

<Stage path="data-table/members-narrow" label="Columns that make room" />

## Dates

`dateColumn` says when, as people do, in the reader's language. Hover or focus shows the full date; it sorts by the date, and a search and the export read it as the date (`2026-11-12T09:30:00.000Z`). Any column whose value is not words to read takes a `text` for them.

<Stage path="data-table/dates" label="Dates" />

## Groups

Rows gathered by owner (`groupingFeature` with `groupBy`), each group counted; a group's heading opens and closes it.

<Stage path="data-table/grouped" label="Groups" />

## Groups kept

`collapsedGroups` keeps the collapsed groups in your state, by value; `location` keeps them in the link. A reload keeps them closed.

<Stage path="data-table/groups-kept" label="Groups kept" />

## Phases as headings

Each group's heading is a heading: a step above a row, its count in a Badge, with room above it so it belongs to its rows. `getGroupVariant` gives a group the warning variant, on its count alone, and it is said in words too. A group's rows stand on the columns' own lines. A closed group is part of the view in the link (`location`), and in a table with a `height` its heading stays under the head while its rows pass.

<Stage path="data-table/workflows" label="Phases as headings" />

## From a server

The server sorts, searches and pages (`rowCount` with `sort`, `query` and `page` in state); placeholders hold the rows' place, then the rows fade in.

<Stage path="data-table/server" label="From a server" />

## Endless

More rows come as the last one scrolls into view, with placeholders while they do.

<Stage path="data-table/endless" label="Endless" />

## Nothing yet, loading, error

Each says so in words, in the rows' place: `emptyState`, `loading` and `error`.

<Stage path="data-table/outcomes" label="Nothing yet, loading, failed" />

## Nothing matches

`noResults` is handed the search and the filter, so the words name them and the action clears them.

<Stage path="data-table/no-match" label="Nothing matches" />

## A view in the link

Sort, search, hide or move a column: the address keeps it (`searchParamsLocation`). Export CSV saves the rows found (`exportFileName`).

<Stage path="data-table/views" label="A view in the link" />

## Density

Compact, default and comfortable rows: 32, 42 and 50px. The words stay the same size.

<Stage path="data-table/density" label="Density" />

## A filter on its own

`DataTableFilters` is the filter a `filterable` table draws, for a page that filters something else: a field, an operator and a value as one joined control. Each field says which operators it takes and whether its value is chosen, a number or words; a shared `compatibilityKey` keeps the value across fields.

<Stage path="data-table/filters" label="A filter on its own" />

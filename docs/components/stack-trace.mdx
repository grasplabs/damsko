## An error and its frames

Stack Trace is a Trace with one row that opens. `StackTraceHeader` is the row's trigger, its line failed, and `StackTraceError` the line's title, the error's `StackTraceErrorType` and `StackTraceErrorMessage` in red; `StackTraceActions` stands beside the trigger, as a button cannot sit inside it; a press opens `StackTraceFrames`, a muted block where the app's own frames stand in ink and the frames from `node_modules` and the runtime stay muted.

<Stage path="stack-trace/basic" label="An error and its frames" />

## Opening a file

With `onFilePathClick`, each frame's path is a button that hands the path, the line and the column to the product, which opens the file there. Without it a path is text: it is never a link made from the stack. `showInternalFrames={false}` leaves out the framework's frames, so the ones you can fix stand alone.

<Stage path="stack-trace/files" label="Opening a file" />

## Firefox and Safari

Their stacks have no error line and write `fn@file:line:column`; the frames read the same. With no children it draws its line, `StackTraceCopyButton` and the frames.

## When to use it

<Intent
  of="stack-trace"
  always={[
    "A tool call or a command that threw, with the frames it sent: `error.stack`, or the AI SDK part's `errorText` when the server sends the stack.",
    "A path that opens the file, through `onFilePathClick`, in development, where the paths are the product's own.",
  ]}
  never={[
    "A failure without frames: say it in the Tool's or Terminal's line.",
    "Stacks from a server in production: they show its file paths.",
  ]}
/>

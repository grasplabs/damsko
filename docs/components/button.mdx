## Variants

Each variant has its own job and its own look. `default` is the one main step of a view, Save changes; never two in one view. `outline`, the quiet fill with a field's edge and lift, is the ordinary button: the lesser action beside a main one, Cancel beside Save, Previous beside Next; and a standalone action or trigger, Invite people, Export, the button that opens a dialog or a menu. `outline` stands anywhere, on a card too. `secondary`, a flat veil with no edge, is for a repeated or dense action, where a row of edged, lifted buttons would be too heavy: the same action on every row of a list, a toolbar of several equal actions. A filter, or anything that is on or off, is a Toggle, not a `secondary` Button: at rest `secondary` wears a pressed toggle's fill. `ghost` is for toolbars, rows and icon buttons, Edit. `destructive` is for what cannot be undone, Delete workspace. `link` is an action that reads as words, Read the guide.

## Beside the main step

Cancel beside Save is `outline`, the lesser button; Save is `default`. Invite people in the section's head stands on its own, an ordinary action, so it is `outline` too.

## The same action on every row

Where the same action repeats down a list, a column of outlined buttons would be too heavy: `secondary` keeps them flat, Duplicate on each row.

<Stage path="button/dense" live label="The same action on every row" />

## Sizes and icons

`default` by default; `sm` in dense tables, `lg` for a main call on touch. `xs`, 28px, is the smallest: a compact button in a card's footer or a prompt input. An icon is a child, `<Icon />`, before or after the words. An icon-only button takes an `icon` size and its name from `aria-label`, which it shows in a tooltip of its own under a resting pointer and on keyboard focus. `tooltip` gives other words (on a button with words too), `tooltip={false}` none; inside a Tooltip of your own the button shows that one. Failed, a `link` turns to the destructive ink alone, with no box.

<Stage path="button/sizes" label="Sizes and icons" />

## As a link

To go somewhere, `asChild` draws the link itself, `<a href>`, so it opens in a new tab on request. Never `onClick`.

<Stage path="button/link" live label="As a link" />

## A press that takes time

It is automatic: when `onClick` returns a Promise, the Button is busy until it settles, takes no second press and shows a spinner, in its icon's place or over its words when it has none, then a tick or the alert for a moment, and the words stay in their place so the width never changes. Failed, it draws the quiet fill with destructive words and edge, whatever its variant. `loadingLabel`, `successLabel` and `errorLabel` are said and shown in place of the words, all stacked so the widest sets the width (an icon-only button says them only). When the page runs the work itself, as a form's submit, it gives `status` instead.

## The same button on every row

Keep the words; give `aria-label` the row's name after them, "Delete Spring launch", so a voice command still finds Delete.

## Out of use, and why

Keep it focusable with `focusableWhenDisabled` and tie the reason to it by `aria-describedby`. Hide what the person can never use here.

## A long name in a narrow head

A label wraps when its room is short. `truncate` keeps it on one line and cuts it with an ellipsis instead, the button shrinking as far as its square, so the control beside it stays in view; its name stays whole.

<Stage path="button/truncate" label="A long name in a narrow head" />

## Every state

Loading keeps focus on the button; success and failure show for a moment, then it rests. The button keeps the width of its widest state, so its results are one or two words ("Saved", "Not sent").
